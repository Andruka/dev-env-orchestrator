# Dev Panel

Локальная веб-панель для рутины: ветки, docker compose, дампы БД, фронтенд.

```sh
dev-panel             # запустить в фоне (если ещё не запущена) и открыть http://localhost:7777
dev-panel stop        # остановить панель (запущенные из неё dup / npm start продолжают работать)
dev-panel restart | status | logs | fg
dev-panel autostart on|off   # запуск в фоне при входе в систему (~/.config/autostart/dev-panel.desktop)
```

Процессы, запущенные из панели (`dup`, `npm start`), не зависят от неё. Их вывод пишется в
`~/.local/state/dev-panel/services/<имя>.log`, и после перезапуска панель снова их подхватывает.

`dev-panel` — ссылка в `~/.local/bin` на `bin/dev-panel`. Ещё панель есть в меню приложений («Dev Panel»).
Node 22+, внешних зависимостей нет. Панель слушает только 127.0.0.1.
События идут в браузер по WebSocket (`/api/ws`), а не через SSE, поэтому открытые вкладки панели не занимают HTTP-соединения браузера.

## Интерфейс

- Сверху показано, что запущено сейчас: какой бэкенд с какой веткой, фронт, PostgreSQL. Отсюда же их можно остановить.
- Слева проекты. Клик или `↑`/`↓` раскрывает проект, `Enter` запускает главное действие, `Esc` сворачивает.
- `Ctrl+K` открывает палитру команд: любое действие для любого проекта, поиск по словам («дамп copy»).
- Справа шаги задачи с прогрессом, лог и вкладки с логами `dup` и `npm start`.
  Во время задачи прогресс видно в заголовке вкладки браузера. Когда задача завершается, приходит уведомление.
- Красным выделены действия, которые удаляют данные. Перед ними всегда спрашивается подтверждение.

## Снимки базы

Хранятся в `~/.local/share/dev-panel/snapshots/<id>/` (`pgdata.tar.zst` + `meta.json`), сжаты zstd.
pgdata копируется только при остановленной БД, поэтому снимок всегда целостный.

| вид | когда создаётся | когда используется | сколько хранится |
|---|---|---|---|
| `fresh` | в конце «Развернуть с нуля», если для этого набора миграций снимка ещё нет | «Развернуть с нуля»: берётся снимок, все миграции которого есть в ветке без изменений; liquibase докатывает только недостающие | 8 последних (`snapshotsKeepFresh`) |
| `dump` | сразу после импорта дампа, до миграций ветки | «Накатить дамп» того же файла (имя + размер + дата): импорт пропускается | 2 последних (`snapshotsKeepDump`) |
| `manual` | кнопка «Сохранить текущую БД» | кнопка ↺ у снимка в списке | пока не удалите |

Сопоставление с веткой идёт по содержимому файлов `src/AusPlan/Database/Migration` с учётом незакоммиченных правок.
Если в снимке есть миграция, которой нет в ветке или которая в ветке изменена, этот снимок не используется.
Перед сохранением проверяется свободное место на диске.

В раскрытой карточке бэкенда показан список всех снимков (они общие для всех копий репозитория).
У каждого снимка свои кнопки «↺ Восстановить» и «✕» (удалить). «Сохранить текущую БД» всегда создаёт новый снимок.

## Скорость

- `ddown`: PostgreSQL останавливается штатно (до 60 с), остальные контейнеры — за 2 с вместо стандартных 10.
- `npm ci` пропускается, если `package-lock.json` и версия node не менялись с прошлой установки
  (метка в `node_modules/.dev-panel-lock`). «npm ci (заново)» переустанавливает всегда.

## Git: только безопасные операции

Панель не может ничего закоммитить или отправить. Разрешено: fetch, checkout ветки, `pull --ff-only`, stash.
`lib/guard.js` проверяет каждую команду перед запуском. В частности, запрещены `commit`, `push`, `merge`, `rebase`, `reset`,
`clean`, `checkout -- <файл>`, `branch -D`, `stash clear` и CLI `gh`/`glab`. Кроме того, у всех git-процессов панели
push-адрес подменён на несуществующий. Значения параметров (ветка, stash, подпись) передаются в команды
только через переменные окружения `P_<имя>`, а не подставляются в текст команды, и перед запуском проверяются по формату.

## Вход во фронтенд

В «⚙ Настройки» задаются логин, пароль и clientId. Они хранятся в `~/.config/dev-panel/secrets.json` (права 600, вне репозитория).
Кнопка «Войти» делает следующее:
1. отправляет `POST /api/login/token` и получает `access_token`, `refresh_token` и `user_id`;
2. запрашивает `GET /api/users/{userId}` и собирает объект `user` так же, как `LoginDialogModal` в CLIENT;
3. через DevTools-протокол записывает это в localStorage вкладки `localhost:3000` и перезагружает её.

### Автоподдержание входа

Refresh-токен на стенде одноразовый, а если обновить его повторно, сервер отвечает **HTTP 200** с `{ error }`.
Клиент обновляет токен только после 401 и ответ не проверяет. Поэтому, если обновить пытаются двое
(две вкладки, повтор запроса), в localStorage записывается `undefined` и сессия ломается.
Панель раз в минуту смотрит токен во вкладке `localhost:3000`:
- до истечения меньше 15 минут — обменивает refresh-токен заранее, и клиент до своего refresh не доходит;
- refresh отклонён или токены сломаны/истекли — входит заново и перезагружает вкладку.

Состояние показано в верхней полосе («Вход»). По клику — проверить сейчас. Выключается в настройках.
Профиль Brave лежит в `~/.config/brave-dev-cors`, а не в `/tmp`: `/tmp` очищается при загрузке системы.

Brave (bbStart) запускается с `--remote-debugging-port=9222`. Если Brave с профилем `/tmp/brave-dev-cors`
уже открыт без этого флага, его нужно закрыть и запустить кнопкой из панели.

## Как устроено

Всё поведение описывается в `config.json`, код менять не нужно.

- **vars** — переменные, доступные в шаблонах как `{имя}`. Также доступны `{project.name}`, `{project.path}` и параметры действия.
- **groups** — группы проектов. Проекты задаются через `paths` или находятся автоматически через `discover`:
  каждая git-папка в `root`, где есть `requireFile`. Ненужные папки убираются через `exclude`.
  `sections` — блоки кнопок на карточке, `primary` — главное действие (кнопка в строке, `Enter`).
- **actions** — действия. Каждое действие — это список шагов. Кнопка «↻ Конфиг» перечитывает файл без перезапуска.

### Поля действия

| поле | смысл |
|---|---|
| `title`, `icon`, `hint` | подпись кнопки, иконка, подсказка |
| `primary` | выделить кнопку |
| `confirm` | спросить подтверждение (поддерживает шаблоны) |
| `danger` | красная кнопка + подтверждение |
| `params` | параметры, которые спрашиваются перед запуском: `gitBranch`, `stash`, `snapshot`, `text`, `file` (`dir`, `ext`), `select` (`options`). В командах доступны как `"$P_<name>"` |
| `steps` | шаги |

### Типы шагов

| type | поля | что делает |
|---|---|---|
| `shell` | `cmd`, `cwd?`, `env?`, `retry?: {times, delayMs}`, `allowFail?` | выполняет bash-команду (cwd по умолчанию — папка проекта) |
| `service` | `service`, `cmd`, `readyPattern?`, `failPattern?`, `env?` | запускает долгоживущий процесс; шаг ждёт строку `readyPattern` в логе |
| `stopService` | `service` | останавливает сервис (SIGINT, затем SIGKILL) |
| `pipeFile` | `file`, `cmd` | передаёт файл в stdin команды и показывает прогресс |
| `detached` | `cmd` | запускает процесс без ожидания (браузер и т.п.) |
| `snapshotRestore` | `kind`, `dataDir`, `migrationsDir` / `dumpFile` / `id`, `flag?` | восстановить pgdata из подходящего снимка; ставит флаг `restored` |
| `snapshotSave` | `kind`, `dataDir`, `stopCmd?`, `startCmd?`, `keep?` | сохранить pgdata в снимок |
| `snapshotDelete` | `id` | удалить снимок |
| `browserAuth` | `url`, `debugPort` | вход по API и запись токенов в localStorage браузера |
| `action` | `action` | вставляет шаги другого действия |

У любого шага могут быть `if` / `unless` — имя флага, который выставил предыдущий шаг (например, `"unless": "restored"`).

Свой тип шага: файл `plugins/steps/<type>.js`, который экспортирует `async (step, ctx) => {}`.
В `ctx` есть `log(line)`, `progress(pct)`, `onCancel(fn)`, `cwd`, `project`, `sleep(ms)`.

## Отличия от bash-алиасов

- `dbRm` удаляет `pgdata` через одноразовый контейнер alpine, а не через `sudo`, поэтому пароль не нужен.
- Дамп накатывается без pgAdmin. Сначала поднимается только контейнер БД, затем выполняются
  `DROP DATABASE ... WITH (FORCE)` и `CREATE DATABASE`, после этого файл передаётся в `psql`.
  В конце выполняются `ddown` и `dup`.
- `dup` считается завершённым, когда `calplanDbScript` выходит с кодом 0 (то есть миграции накатились).
- `npm start` запускается с `BROWSER=none`, а браузер открывает кнопка bbStart.

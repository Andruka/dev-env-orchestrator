# Dev Panel

Локальная веб-панель для рутины: ветки, docker compose, дампы БД, фронтенд.

```sh
./start.sh            # http://localhost:7777
```

Node 18+, внешних зависимостей нет. Панель слушает только 127.0.0.1.
При остановке панели (Ctrl+C) останавливаются запущенные ею процессы (`dup`, `npm start`).

## Как устроено

Всё поведение описывается в `config.json`, код менять не нужно.

- **vars** — переменные, доступные в шаблонах как `{имя}`. Также доступны `{project.name}`, `{project.path}` и параметры действия.
- **groups** — группы проектов. Проекты задаются через `paths` или находятся автоматически через `discover`:
  каждая git-папка в `root`, где есть `requireFile`. Ненужные папки убираются через `exclude`.
  `actions` — кнопки на карточке проекта.
- **actions** — действия. Каждое действие — это список шагов. Кнопка «↻ Конфиг» перечитывает файл без перезапуска.

### Поля действия

| поле | смысл |
|---|---|
| `title`, `icon`, `hint` | подпись кнопки, иконка, подсказка |
| `primary` | выделить кнопку |
| `confirm` | спросить подтверждение (поддерживает шаблоны) |
| `params` | параметры, которые спрашиваются перед запуском: `gitBranch`, `file` (`dir`, `ext`), `select` (`options`) |
| `steps` | шаги |

### Типы шагов

| type | поля | что делает |
|---|---|---|
| `shell` | `cmd`, `cwd?`, `env?`, `retry?: {times, delayMs}`, `allowFail?` | выполняет bash-команду (cwd по умолчанию — папка проекта) |
| `service` | `service`, `cmd`, `readyPattern?`, `failPattern?`, `env?` | запускает долгоживущий процесс; шаг ждёт строку `readyPattern` в логе |
| `stopService` | `service` | останавливает сервис (SIGINT, затем SIGKILL) |
| `pipeFile` | `file`, `cmd` | передаёт файл в stdin команды и показывает прогресс |
| `detached` | `cmd` | запускает процесс без ожидания (браузер и т.п.) |
| `action` | `action` | вставляет шаги другого действия |

Свой тип шага: файл `plugins/steps/<type>.js`, который экспортирует `async (step, ctx) => {}`.
В `ctx` есть `log(line)`, `progress(pct)`, `onCancel(fn)`, `cwd`, `project`, `sleep(ms)`.

## Отличия от bash-алиасов

- `dbRm` удаляет `pgdata` через одноразовый контейнер alpine, а не через `sudo`, поэтому пароль не нужен.
- Дамп накатывается без pgAdmin. Сначала поднимается только контейнер БД, затем выполняются
  `DROP DATABASE ... WITH (FORCE)` и `CREATE DATABASE`, после этого файл передаётся в `psql`.
  В конце выполняются `ddown` и `dup`.
- `dup` считается завершённым, когда `calplanDbScript` выходит с кодом 0 (то есть миграции накатились).
- `npm start` запускается с `BROWSER=none`, а браузер открывает кнопка bbStart.

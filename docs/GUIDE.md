## 1. Установка

### Что нужно заранее

Панель не устанавливает системные программы — это нужно сделать самому (один раз):

| что | зачем | как поставить (Ubuntu/Debian) |
|---|---|---|
| **Linux** с графической сессией | панель рассчитана на Linux | — |
| **Node.js 22+** | запускает саму панель | <https://nodejs.org> (LTS) или `nvm install 22` |
| **git** | ветки, статус репозиториев | `sudo apt install git` |
| **docker** + плагин **compose** | бэкенд и БД | <https://docs.docker.com/engine/install/> |
| **zstd** | сжатие снимков БД | `sudo apt install zstd` |
| **Brave, Chrome или Chromium** | окно панели и фронтенд | с сайта браузера |
| `xdotool` *(необязательно)* | повторный запуск поднимает уже открытое окно | `sudo apt install xdotool` |

Два шага, которые нельзя сделать за вас:

1. **Доступ к docker без sudo:** `sudo usermod -aG docker $USER`, затем выйти из системы и войти снова.
2. **Один раз открыть браузер** и пройти его «первый запуск» (если им ещё не пользовались), иначе окно панели может показать приветственные диалоги.

Проверить, всё ли на месте, можно после установки командой `dev-panel doctor` или в «Настройки → Проверка».

### Установщик

Получите файл `dev-panel-<версия>.run` (его собирают командой `npm run build:installer`, см. [раздел 13](#13-для-тех-кто-развивает-панель)) и выполните:

```sh
chmod +x dev-panel-1.0.0.run
./dev-panel-1.0.0.run
```

Установщик:

1. проверяет Node.js, git, docker, zstd;
2. копирует панель в `~/.local/share/dev-panel/app`, создаёт команду `~/.local/bin/dev-panel` и значок **Dev Panel** в меню приложений;
3. задаёт вопросы (все можно пропустить Enter'ом): папка с репозиториями CalPlan, адрес фронтенда, браузер, логин для входа;
4. предлагает включить запуск при входе в систему и запустить панель.

Параметры: `--yes` (без вопросов), `--no-setup` (только файлы), `--no-start`, `--prefix ДИР` (куда ставить), `--uninstall`, `--uninstall --purge`.
Если `~/.local/bin` нет в `PATH`, установщик скажет, что добавить в `~/.bashrc`.

### Из каталога с исходниками

```sh
git clone <адрес репозитория> dev-panel && cd dev-panel
ln -s "$PWD/bin/dev-panel" ~/.local/bin/dev-panel
dev-panel setup        # интерактивная настройка
dev-panel desktop      # значок в меню приложений
```

## 2. Первый запуск

`dev-panel` запускает панель в фоне и открывает её в отдельном окне (браузер в режиме приложения: без вкладок и адресной строки, своя иконка в панели задач). Закрытие окна **не** останавливает панель и запущенные из неё процессы.

Если репозитории ещё не выбраны, панель покажет экран приветствия:

1. **Репозитории → «Корневая папка CalPlan»** — выберите папку через проводник. От неё считаются папка клиента, дампы (`dbDumps`) и данные БД (`calplanDb`).
2. **Проверка** — зелёные галочки значат, что всё есть; красное и жёлтое снабжено подсказкой «что сделать».
3. **Вход** — логин и пароль для фронтенда (по желанию).

Всё, что спрашивает установщик, меняется потом в **Настройках** (шестерёнка справа вверху или `Ctrl`+`,`).

### Что пользователь настраивает вручную

| настройка | где |
|---|---|
| установить Node.js 22+, git, docker, zstd, браузер | [раздел 1](#1-установка) |
| добавить себя в группу `docker` и перезайти | [раздел 1](#1-установка) |
| папка с репозиториями CalPlan | установщик / «Настройки → Репозитории» |
| логин и пароль для фронтенда | установщик / «Настройки → Стенды → Общий вход» |
| адрес фронтенда, порты, имя файла compose, папки дампов и БД | только если отличаются от стандартных: «Настройки → Пути и порты» |

Остальное (порт панели `7777`, профиль браузера, имена сервисов, хранение снимков) уже имеет разумные значения.

## 3. Интерфейс

- **Верхняя полоса** — что запущено сейчас: бэкенд (какой и на какой ветке), фронтенд, PostgreSQL, стенд, состояние входа и выполняющаяся задача. Отсюда запущенное можно остановить. **Плашка «Стенд» — выпадающий список:** клик (или `Enter`) открывает стенды, выбор применяет его без захода в настройки; `↑`/`↓` — навигация, `Esc` — закрыть.
- **Слева — проекты** по группам. Клик (или `↑`/`↓`) раскрывает карточку с кнопками, `Enter` запускает **главное** действие, `Esc` сворачивает. Значки у строки: ✎ — есть незакоммиченные файлы, ↓/↑ — отстаёт/опережает upstream, архив — есть stash.
- **Справа — консоль:** ход задачи по шагам, лог, вкладки долгоживущих процессов (`compose`, `frontend`). Во время задачи прогресс виден в заголовке вкладки, по завершении приходит уведомление: тост, а если окно панели не в фокусе — ещё и системное уведомление и короткий звук (настраивается в «Оформление → Уведомления»). В логе есть **фильтр строк** (оставляет строки с введённым текстом, `Esc` очищает), переключатель переноса, «Сохранить» (файл `.log` в папке загрузок), «Копировать» и «К концу». Под ходом задачи — **история запусков** (последние 50, с логами); она сохраняется в `~/.local/state/dev-panel/jobs.json` (права 600) и переживает перезапуск панели. Границу между колонками можно перетащить.
- **Красные кнопки** удаляют данные; перед ними всегда спрашивается подтверждение.
- **Палитра команд** `Ctrl`+`K`: любое действие для любого проекта, переход в настройки, смена темы. Поиск по словам: «дамп server».

Подсказка `Enter` прямо на главной кнопке выбранного проекта напоминает о горячей клавише.

Горячие клавиши: `Ctrl+K` палитра · `↑`/`↓` выбор проекта · `Enter` главное действие · `Esc` свернуть/закрыть · `Ctrl+,` настройки · `?` справка · `/` поиск проекта.

Процессы, запущенные из панели (`dup`, `npm start`), не зависят от неё. Их вывод пишется в `~/.local/state/dev-panel/services/<имя>.log`, после перезапуска панель снова их подхватывает. Панель и каждый такой процесс (и браузер) запускаются в своём systemd-scope (`dev-panel-*.scope`): когда `systemd-oomd` при нехватке памяти убивает прожорливую группу процессов (например, вкладку терминала), панель и сервисы не гибнут вместе с ней.

## 4. Репозитории

«Настройки → Репозитории».

- **Корневая папка CalPlan** — главный параметр; от неё считаются остальные пути.
- У каждой **группы** (Бэкенд, Фронтенд) есть список проектов и **папка автопоиска**: все git-папки внутри неё (у бэкенда — только те, где есть файл compose) появляются сами.
- **«Добавить репозиторий»** открывает проводник. Папки с git помечены, кнопка «+» в строке выбирает репозиторий сразу.
- **«Убрать»** прячет репозиторий в панели. Папка на диске остаётся; вернуть можно, добавив её снова.
- **«Новая группа…»** создаёт свою группу проектов (например, «Сервисы»). Группа бывает *обычной* (git + свои кнопки), *node* (понимает `npm start`) или *docker compose* (показывает контейнеры).
- **«Сбросить»** возвращает репозитории, скрытые кнопки и главное действие группы к значениям по умолчанию.

## 5. Кнопки: свои, системные, скрытые

«Настройки → Кнопки». Выберите группу — увидите все кнопки её карточки по разделам.

| значок | что делает |
|---|---|
| ⚡ | сделать кнопку **главной** (она в строке проекта, её запускает `Enter`) |
| ✎ | изменить |
| глаз | **скрыть** / показать (кнопка остаётся в списке «Скрытые») |
| ↺ | **сбросить к исходному** (у изменённых системных кнопок) |
| корзина | удалить (только свои кнопки) |

**Системные** кнопки (из поставки панели) нельзя удалить, но можно скрыть и изменить; метка «изменена» подсвечивает правки, а ↺ возвращает исходное поведение. Обновления панели не затирают ваши правки.

### Новая кнопка

«Новая кнопка…» открывает редактор:

- **Название, иконка, подсказка.**
- **Шаблоны** — готовые заготовки: открыть в VS Code, терминал в папке, история коммитов, `npm test`, логи compose.
- **Опасная** — красная, перед запуском спросит подтверждение (можно задать свой текст).
- **Параметры** — что спросить перед запуском: ветка git, запись stash, файл из папки, текст, выбор из списка. В командах значение доступно как `"$P_имя"` (так оно безопасно попадает в bash), в заголовках — как `{имя}`.
- **Шаги** — выполняются по порядку; ошибка останавливает цепочку.
- **Где показывать** — в каких группах и в каком разделе карточки.
- Кнопка **JSON** — прямое редактирование (для опытных).

Пример: кнопка «Тесты» с шагом `npm test` в группе «Фронтенд»; кнопка «Логи БД» с командой `{dc} logs --tail 200 {dbService}`.

### Типы шагов

| type | поля | что делает |
|---|---|---|
| `shell` | `cmd`, `cwd?`, `env?`, `retry?: {times, delayMs}`, `allowFail?` | выполняет bash-команду (по умолчанию в папке проекта) |
| `service` | `service`, `cmd`, `readyPattern?`, `failPattern?`, `env?` | запускает долгоживущий процесс; шаг ждёт строку `readyPattern` в логе |
| `stopService` | `service` | останавливает процесс (SIGINT, затем SIGKILL) |
| `pipeFile` | `file`, `cmd` | передаёт файл в stdin команды и показывает прогресс |
| `detached` | `cmd` | запускает процесс без ожидания (браузер, GUI) |
| `snapshotRestore` | `kind`, `dataDir`, `migrationsDir` / `dumpFile` / `id`, `flag?` | восстанавливает pgdata из подходящего снимка, ставит флаг `restored` |
| `snapshotSave` | `kind`, `dataDir`, `stopCmd?`, `startCmd?`, `keep?` | сохраняет pgdata в снимок |
| `snapshotDelete` | `id` | удаляет снимок |
| `browserAuth` | `url`, `debugPort`, `clearCache?` | вход по API и запись токенов в localStorage браузера; перед этим чистит кеш браузера (куки и localStorage не трогает), `clearCache: false` отключает |
| `action` | `action` | вставляет шаги другой кнопки |

У любого шага может быть `if` / `unless` — имя флага, выставленного предыдущим шагом (например, `"unless": "restored"`).

### Переменные в командах

`{project.path}`, `{project.name}`, а также все значения из «Настройки → Пути и порты»: `{calplanRoot}`, `{dumpsDir}`, `{dbDataDir}`, `{composeFile}`, `{dbService}`, `{dbName}`, `{frontendUrl}`, `{debugPort}`, `{browserCmd}`, `{dc}` (= `docker compose -f {composeFile}`) и другие. Неизвестные имена остаются как есть.

### Что кнопка не может

Правила безопасности действуют и для ваших команд ([раздел 9](#9-git-только-безопасные-операции)): `git commit/push/merge/rebase/reset`, `gh`, `glab` будут отклонены ещё при сохранении кнопки.

Свой тип шага: файл `plugins/steps/<type>.js` рядом с панелью, экспортирует `async (step, ctx) => {}`; в `ctx` есть `log(line)`, `progress(pct)`, `onCancel(fn)`, `cwd`, `project`, `sleep(ms)`.

Эти темы — переработанные вариации открытых палитр (оттенки подогнаны под AA, поэтому не совпадают с оригиналом побуквенно): Catppuccin, Tokyo Night (folke), Gruvbox (morhetz), Everforest (sainnhe), Kanagawa (rebelot), Flexoki (Стивен Анго), Rosé Pine, Solarized, Dracula, One Dark, Monokai Pro, Oxocarbon, Poimandres, Vesper. ## 7. Вход во фронтенд

В «Настройки → Стенды → Общий вход» задаются логин, пароль и clientId. Они хранятся в `~/.config/dev-panel/secrets.json` (права 600, вне репозитория и **не** попадают в резервную копию настроек). Кнопка «Войти»:

1. отправляет `POST` на URL токена и получает `access_token`, `refresh_token` и `user_id`;
2. запрашивает данные пользователя и собирает объект `user` так же, как `LoginDialogModal` в CLIENT;
3. через DevTools-протокол записывает это в localStorage вкладки фронтенда и перезагружает её.

Адреса API меняются там же (по умолчанию — внутренний стенд). Кнопка «Проверить вход» проверяет связку логин/пароль.

### Автоподдержание входа

Refresh-токен на стенде одноразовый, а при повторном обновлении сервер отвечает **HTTP 200** с `{ error }`. Клиент обновляет токен только после 401 и ответ не проверяет, поэтому, если обновить пытаются двое (две вкладки, повтор запроса), в localStorage записывается `undefined` и сессия ломается. Панель раз в минуту смотрит токен во вкладке фронтенда:

- до истечения меньше 15 минут — обменивает refresh-токен заранее, и клиент до своего refresh не доходит;
- refresh отклонён или токены сломаны/истекли — входит заново и перезагружает вкладку.

Состояние показано в верхней полосе («Вход»); клик — проверить сейчас. Выключается в настройках.

Браузер кнопки «Браузер» запускается с `--remote-debugging-port` (по умолчанию `9222`) и своим профилем (`~/.config/brave-dev-cors`) без CORS. Если браузер с этим профилем уже открыт без порта отладки, закройте его и запустите кнопкой из панели.

## 7a. Стенды: подключение к разным окружениям

Ветки могут работать с разными стендами. К какому стенду подключена ветка, определяют файлы: `.env` бэкенда (например, `BASIC_PRODUCT_PORT`) и `public/config.js` фронтенда (`BACKEND_URL`). Вместо ручной подмены панель держит рядом готовые варианты и переключает их.

**Форма стенда.** Обязательны только название и файлы; «Вход и адрес бэкенда», «Страница фронтенда» и «Переменные для IDE» свёрнуты и раскрываются сами, если в них есть значения или ошибка. Ошибки показываются у поля, а при закрытии настроек с несохранённым стендом панель спрашивает подтверждение (фокус стоит на «Отмена»).

**Быстрый путь.** «Настройки → Стенды → Новый стенд»: назовите стенд (например, `5008`), для бэкенда и фронтенда выберите файл, логин и пароль. Откуда взять файл:
- «Взять то, что лежит в репозитории сейчас» — подойдёт, если вы уже настроили `.env` и `config.js` вручную;
- готовый вариант, найденный в репозитории (`.env_5008`, `public/config5008.js`);
- файл с диска: укажите полный путь, например `~/secrets/.env_5008`.

Файлы копируются в папку панели `~/.config/dev-panel/stands/` (права 600), то есть хранятся вне репозиториев и в git не попадают. В репозитории ничего не создаётся, а старые `.env_5008` из него потом можно удалить. Если снять галочку «Хранить файлы в панели», стенд будет ссылаться на файлы в репозитории.

**Страница фронтенда у каждого стенда своя.** В форме стенда есть поле «Страница фронтенда» (например, `http://localhost:3000/objects/1841/plans`): id объекта в адресе зависит от базы, а базы у стендов разные. Её открывают «Браузер», «Запустить и войти» и т. п., когда фронтенд подключён к этому стенду (по `BACKEND_URL` из `config.js`). Если поле пусто, берётся общий адрес из «Пути и порты».

**Состояние приложения в браузере не смешивается между стендами.** В localStorage фронтенд хранит последний открытый объект, режимы и пользователя; всё это относится к базе конкретного стенда. Панель помечает localStorage адресом стенда (ключ `devpanel:stand`) и при входе под другим стендом стирает остальное (кроме языка `i18nextLng`), записывает новые токены и пользователя. Автопродление при смене стенда открывает стартовую страницу нового стенда. Один раз это сработает и при первом входе после обновления панели (метки ещё нет).

**Сверка стенда фронтенда и бэкенда.** Токен выдаёт стенд, а локальный бэкенд проверяет его своим `PUBLIC_KEY`. Если фронтенд и вход идут на стенд 5008, а бэкенд (например, запущенный из IDE) работает с окружением 5005, все запросы к бэкенду получат 401 и страницы не загрузятся. Поэтому в верхней панели есть индикатор «Стенд»: панель берёт из `config.js` все `BACKEND_URL*`, находит процесс, слушающий локальный адрес (например, `BACKEND_URL_PLANS: 'http://localhost:9000'`), читает его окружение (`BASIC_PRODUCT_HOST` и `BASIC_PRODUCT_PORT`) и сравнивает со стендом фронтенда. При расхождении индикатор жёлтый: перезапустите бэкенд с окружением нужного стенда (переменные — кнопка «Для IDE») или переключите стенд. Окружение читается только у ваших процессов; у процесса без этих переменных (например, внутри docker) стенд считается неизвестным и предупреждения нет.

**Переменные для IDE** тоже закрепляются за стендом: в форме есть поле «Вставьте пачкой» (строки `KEY=VALUE`, целый `.env` или одна строка `A=1;B=2`). Когда стенд включён, они накладываются поверх значений из `.env` и попадают в кнопку «Для IDE» и в файл для EnvFile. Хранятся в `~/.config/dev-panel/stands-ide/` (права 600), а не в `config.json`, и в экспорт настроек не входят.

Адрес бэкенда панель берёт из `BACKEND_URL` выбранного `config.js` (или укажите вручную), и логин с паролем подставляются, когда фронтенд подключён к этому адресу. В карточке репозитория стенды показаны кнопками: одно нажатие меняет `.env` и `config.js` сразу, а выпадающие списки позволяют сменить один файл. Если в группе несколько репозиториев, файл меняется у выбранного (раскрытого) или у единственного запущенного; в форме стенда репозиторий выбирается отдельно. Какой вариант сейчас стоит, панель определяет по содержимому файла. Если там что-то своё, что не совпадает ни с одним вариантом, будет «своё содержимое», а кнопка «Сохранить в панель…» превратит его в новый вариант в библиотеке.

**Что нужно знать**
- Вступает в силу после перезапуска: бэкенд читает `.env` при запуске (кнопка `dup`), фронтенд — при загрузке страницы (после смены обновите её или нажмите «Запустить и войти»).
- Перед перезаписью файла с вашими ручными правками копия кладётся в `~/.local/state/dev-panel/swap-backups/` (последние 10 на репозиторий).
- Если файл отслеживается git (так бывает с `.env` в репозитории бэкенда), рядом стоит значок «в git»: смена стенда видна как изменение, а `git checkout` на ветку с другим `.env` может отказать. Панель ничего не коммитит: перед коммитом верните исходный файл.
- Варианты, которых нет в git и которые не скрыты (например, добавленный вами `.env_5008`), помечены «не отслеживается git», а рядом появляется кнопка «Скрыть варианты от git». Плашка «.env отслеживается git» — про сам подменяемый файл: он уже в репозитории, поэтому смена стенда видна в git как изменение. Она дописывает файлы в `.git/info/exclude` репозитория. Это локальный файл, он не коммитится и не уходит на сервер, так что `git status` перестанет предлагать такие файлы к коммиту. Файлы в `.env` содержат пароли и ключи, поэтому в общий репозиторий их лучше не добавлять.
- Какие файлы подменяются и по каким маскам ищутся варианты, меняется в «Настройки → Стенды → Дополнительно»; можно добавить свои (например, `appsettings.json`). Системные слоты можно сбросить.

**Вход во фронтенд следует за стендом.** Адрес логина берётся из `BACKEND_URL` активного `config.js` (хост и порт), а путь — из «Настройки → Стенды → Общий вход». Поэтому после смены стенда «Запустить и войти» ходит на нужный сервер.

**Логин и пароль у каждого стенда свои.** Обычно они задаются прямо в форме стенда. Отдельный список есть в «Настройки → Стенды → Общий вход → Учётные данные по стендам»: там для адреса бэкенда (например, `https://10.145.1.150:5008`) задаются логин, пароль и при необходимости clientId. Панель подставляет их по адресу из активного `config.js`; для стенда без записи берутся общие данные из верхней формы. Пароли лежат в `~/.config/dev-panel/secrets.json` (права 600) и не попадают в экспорт настроек и бэкапы. Папка `stands/` с файлами стендов тоже в экспорт не входит. После смены стенда автопродление замечает другой адрес и входит заново под учётными данными нового стенда, а вкладка фронтенда перезагружается. Отключается переключателем «Вход следует за стендом» в «Пути и порты → Фронтенд и браузер».

**Запуск из IDE.** Кнопка «Для IDE» рядом с `.env` показывает переменные текущего стенда: копируйте построчно или одной строкой через `;` и вставляйте в Environment variables запуска. Постоянный файл (например, для плагина EnvFile) лежит в `~/.local/state/dev-panel/ide/<репозиторий>.env` и обновляется при каждой смене стенда в панели. Если в IDE часть значений отличается от файла (например, `CP_DB_HOST=localhost` вместо имени docker-сервиса), впишите их в «Свои значения для IDE» в настройках слота: они добавляются поверх значений из файла.

## 7b. Swagger

Группа **Swagger** собирает и запускает спецификацию API из вашего репозитория `swagger` (в нём лежат `build.sh`, `start.sh` и `docker-compose.yml`).

- **Путь.** По умолчанию `{calplanRoot}/swagger`; свой путь задаётся в «Пути и порты → Swagger» (переменная `swaggerDir`), там же порты UI (9105), редактора (9104) и mock (4010). У каждого пользователя путь свой, в профиль для коллег он не попадает.
- **Кнопки:** «Собрать и запустить» (`build.sh`, главная, `Enter`), «Запустить (UI + mock)» (`start.sh`), «Открыть Swagger UI», «Открыть mock», «Редактор», «Проверить спецификацию», «Остановить», «Открыть папку».
- **Открыть в браузере.** «Открыть Swagger UI» сначала проверяет, что порт отвечает, и только потом открывает `http://localhost:<порт>`; если нет — подсказывает нажать «Запустить». Те же кнопки есть на плашке Swagger в верхней полосе.
- Если папки нет, «Обслуживание → Проверка» покажет предупреждение; пока не задан корень проектов, путь Swagger не подставляется.

## 8. Снимки базы данных

Хранятся по умолчанию в `~/.local/share/dev-panel/snapshots/<id>/` (`pgdata.tar.zst` + `meta.json`), сжаты zstd. pgdata копируется только при остановленной БД, поэтому снимок всегда целостный.

| вид | когда создаётся | когда используется | сколько хранится |
|---|---|---|---|
| `fresh` | в конце «Развернуть с нуля», если для этого набора миграций снимка ещё нет | «Развернуть с нуля»: берётся снимок, все миграции которого есть в ветке без изменений; liquibase докатывает только недостающие | 8 последних (`snapshotsKeepFresh`) |
| `dump` | сразу после импорта дампа, до миграций ветки | «Накатить дамп» того же файла (имя + размер + дата): импорт пропускается | 2 последних (`snapshotsKeepDump`) |
| `manual` | кнопка «Сохранить текущую БД» | кнопка «Восстановить» у снимка в списке | пока не удалите |

Сопоставление с веткой идёт по содержимому файлов `src/AusPlan/Database/Migration` с учётом незакоммиченных правок. Если в снимке есть миграция, которой нет в ветке или которая изменена, снимок не используется. Перед сохранением проверяется свободное место на диске (снимок занимает несколько гигабайт). В карточке бэкенда виден список снимков и сколько места они занимают; у каждого свои кнопки «Восстановить» и «✕».

**Папка и отключение.** «Настройки → Пути и порты → Снимки БД» (при установке тоже спрашивается):
- **Папка для снимков** (`snapshotsDir`) — абсолютный путь или `~/…`. Один снимок занимает несколько ГБ, поэтому при нехватке места на домашнем диске можно указать другой диск. При смене папки уже сохранённые снимки не переносятся: скопируйте папки `<id>` в новое место сами (или создайте снимки заново), старую можно удалить.
- **Создавать снимки БД** (`snapshotsEnabled`) — «Нет» отключает создание: «Развернуть с нуля» и «Накатить дамп» работают как обычно, но ничего не сохраняют (в логе будет «Создание снимков отключено»), БД при этом не останавливается ради копирования; кнопка «Сохранить текущую БД» сообщит, что снимки отключены. Уже сохранённые снимки остаются в списке и по-прежнему восстанавливаются и удаляются.
- Хранимое количество — `snapshotsKeepFresh` и `snapshotsKeepDump` там же.

**Скорость:** `ddown` останавливает PostgreSQL штатно (до 60 с), остальные контейнеры — за 2 с вместо 10. `npm ci` пропускается, если `package-lock.json` и версия node не менялись (метка в `node_modules/.dev-panel-lock`); «npm ci (заново)» переустанавливает всегда.

**Отличия от bash-алиасов:** `dbRm` удаляет `pgdata` через одноразовый контейнер alpine, а не `sudo`; дамп накатывается без pgAdmin (поднимается только контейнер БД, затем `DROP DATABASE … WITH (FORCE)`, `CREATE DATABASE` и `psql`); `dup` считается завершённым, когда `calplanDbScript` выходит с кодом 0 (миграции накатились); `npm start` запускается с `BROWSER=none`.

## 9. Git: только безопасные операции

Панель не может ничего закоммитить или отправить. Разрешены: fetch, checkout ветки, `pull --ff-only`, stash, чтение. `lib/guard.js` проверяет каждую команду перед запуском — в том числе ваши кнопки. Запрещены `commit`, `push`, `merge`, `rebase`, `reset`, `clean`, `checkout -- <файл>`, `branch -D`, `stash clear` и CLI `gh`/`glab`. Кроме того, у всех git-процессов панели push-адрес подменён на несуществующий. Значения параметров (ветка, stash, подпись) передаются в команды только через переменные окружения `P_<имя>` и проверяются по формату.

**Доступ к самой панели.** Она отвечает только на запросы с `localhost`/`127.0.0.1`, а запросы с чужим `Origin` (с других сайтов) отклоняет — иначе любая открытая страница могла бы запускать команды от вашего имени.

## 10. Командная строка

```sh
dev-panel              # запустить в фоне (если ещё не запущена) и открыть окно
dev-panel web          # то же, но во вкладке обычного браузера
dev-panel stop         # остановить панель (dup и npm start продолжают работать)
dev-panel restart | status | logs | fg
dev-panel setup        # интерактивная настройка (можно запускать повторно)
dev-panel doctor       # проверка окружения
dev-panel autostart on|off   # запуск при входе в систему
dev-panel desktop on|off     # значок в меню приложений
dev-panel version
```

Окно — браузер в режиме `--app`. Браузер берётся так: `$DEV_PANEL_BROWSER`, затем «Команда браузера» из настроек, затем brave-browser, google-chrome, chromium. Профиль окна — `~/.config/dev-panel/app-browser`.

## 11. Перенос настроек, обновление, удаление

**Где что лежит**

| что | где |
|---|---|
| ваши настройки (репозитории, кнопки, переменные, тема) | `~/.config/dev-panel/config.json` |
| логин и пароль | `~/.config/dev-panel/secrets.json` |
| логи процессов и панели | `~/.local/state/dev-panel/` |
| снимки БД | `~/.local/share/dev-panel/snapshots/` (меняется в «Пути и порты → Снимки БД») |

**Резервная копия.** «Настройки → Справка → Сохранить в файл» выгружает репозитории, кнопки, переменные и тему одним JSON (пароль не включается). «Загрузить из файла» применяет такой файл — так можно перенести настройки на другой компьютер или поделиться своими кнопками с коллегой. Пути в копии абсолютные: после переноса проверьте «Репозитории».

**Обновление:** запустить новый `.run` — он остановит панель, заменит файлы и сохранит настройки; запущенные `dup` и `npm start` не пострадают.

**Удаление:** `./dev-panel-<версия>.run --uninstall` (настройки и снимки остаются) или `--uninstall --purge` (с подтверждением удаляет всё).

## 11a. Обслуживание, диагностика и обновление

«Настройки → Обслуживание» — четыре подвкладки:

- **Проверка** — окружение (Node, git, docker, zstd, браузер, Swagger, место в домашней папке). При запуске панель делает проверку сама и показывает над проектами плашку, только если есть красное.
- **Диск** — что занимает место: снимки (с лишними по политике «хранить свежих»), дампы, резервные копии подмены файлов, образы и кэш сборки docker. Каждое удаление — отдельная кнопка с подтверждением, сама панель ничего не чистит.
- **Журнал** — что и когда делала панель: задачи, смена стенда, освобождение портов, очистка, обновление. Пароли и значения переменных не пишутся. Файл `~/.local/state/dev-panel/journal.jsonl` (права 600).
- **Обновления и профиль** — версия, «Что нового», проверка и установка обновления (для установки из git: `git pull --ff-only` и перезапуск; отказ, если идёт задача, есть локальные изменения или коммиты, которых нет на сервере), экспорт и импорт **профиля для коллег**: репозитории, кнопки, переменные и стенды без личных путей, паролей и IDE-переменных; при импорте существующие стенды и пути не перезаписываются.

**Подсказки при ошибках.** Если задача упала, под ней появляются до трёх готовых решений: порт занят (кнопка «Освободить порт» останавливает контейнер или ваш процесс), docker не запущен или нет прав, нет места, локальные изменения мешают checkout/pull, ветки нет, нет доступа по ssh, 401/403 при входе, zstd, лимит inotify, ошибка миграции.

**Несовпадение стендов.** Красная плашка «стенды различаются» открывает окно: переключить на стенд бэкенда или фронтенда, показать переменные IDE, освободить порт процесса, запущенного не на том стенде.

**Проверка соединения со стендом** (в карточке стенда): адрес отвечает, учётные данные приняты, вход выполняется и данные пользователя доступны; ничего не меняется.

**Мастер первого запуска** — 5 шагов (корень проектов → вход → стенд → Swagger → готово). Открывается сам при первом запуске, потом — «Мастер настройки» на приветственной карточке.

**Поиск проектов.** Когда проектов больше трёх, над списком появляется поле поиска; `/` ставит в него курсор, `Esc` очищает. Текущая ветка подсвечена: основная нейтрально, рабочая — акцентом.

**Снимки** помнят, на каком стенде и ветке сделаны; при откате на другой стенд панель предупреждает.

## 12. Если что-то не работает

Сначала откройте **«Настройки → Проверка»** (или `dev-panel doctor`) — большинство причин видно сразу.

| симптом | что делать |
|---|---|
| Окно не открывается | `dev-panel logs`; задайте браузер в «Настройки → Пути и порты» или `DEV_PANEL_BROWSER` |
| «Порт 7777 занят другим экземпляром» | панель уже запущена не через `dev-panel`; либо поменяйте порт: в `config.json` в `vars` добавьте `"port": 7790` |
| Нет репозиториев | выберите корневую папку CalPlan в «Репозитории» |
| `permission denied` у docker | `sudo usermod -aG docker $USER`, перезайти в систему |
| Снимок не создаётся | нужен `zstd` и свободное место (несколько ГБ) |
| «Войти» не работает | проверьте логин в «Настройки → Стенды → Общий вход», «Проверить вход»; браузер должен быть запущен кнопкой «Браузер» (с портом отладки) |
| Команды в «Браузер» не видят Brave | закройте Brave с этим профилем и запустите из панели |
| Кнопка не сохраняется: «команда запрещена» | панель не выполняет `commit/push/merge/reset` — это защита, а не ошибка |
| Хочу вернуть всё как было | «Репозитории → Сбросить», у кнопок — ↺, или удалите `~/.config/dev-panel/config.json` |

## 13. Для тех, кто развивает панель

```
server.js            HTTP + WebSocket, маршруты API
defaults.json        поставляемые группы, кнопки, переменные (системные значения)
lib/config.js        defaults.json + пользовательский конфиг → итоговый конфиг
lib/userConfig.js    ~/.config/dev-panel/config.json
lib/admin.js         изменения настроек (репозитории, кнопки, переменные, тема)
lib/runner.js        выполнение кнопок по шагам; lib/steps/*  типы шагов
lib/guard.js         защита git; lib/services.js  долгоживущие процессы
lib/envswap.js       стенды: подмена .env / config.js, пресеты, выгрузка для IDE
lib/standCheck.js   сверка стенда фронтенда и локального бэкенда
lib/stands.js       стенд целиком: файлы в библиотеке панели, адрес, логин и пароль
lib/doctor.js        проверка окружения; lib/cli.js  setup/doctor из терминала
public/              интерфейс (без сборки): app.js, settings.js, stands.js, dialogs.js, themes.css …
scripts/             build-installer.sh, check-contrast.js, sandbox.sh
test/                node --test
```

- Тесты: `npm test`. Включает дымовой тест интерфейса (`test/ui.test.js`): он запускает песочницу и headless Chrome/Brave/Chromium, обходит настройки, темы, лог и меню стенда; без браузера или с `DEV_PANEL_SKIP_UI=1` пропускается. Проверка контраста тем: `node scripts/check-contrast.js`.
- Изолированный экземпляр для проверок (свой HOME, порт, тестовые репозитории): `scripts/sandbox.sh [порт]`. Рабочую панель он не трогает.
- Установщик: `npm run build:installer` → `dist/dev-panel-<версия>.run` + `.sha256`. Версия берётся из `package.json`.
- Системные кнопки — это `defaults.json`: пользовательские правки лежат отдельно, поэтому обновление поставки их не затирает. Поле `"internal": true` скрывает кнопку из редактора (ею пользуется интерфейс, например «Восстановить» у снимка).
- Иконки — Lucide (ISC), шрифты — Inter и JetBrains Mono (OFL); лицензии в `public/vendor` и `public/fonts`.
